* Introduction

Loku is a local video browser and player.  Point it at one or more media
directories and get a browseable, searchable interface in your web browser.

It pairs well with [[https://github.com/yt-dlp/yt-dlp][yt-dlp]] (download a channel's videos alongside their metadata
and thumbnails) and with [[https://www.makemkv.com/][MakeMKV]] disc rips, which it turns into first-class
library items: friendly titles from Kodi =.nfo= sidecars or cleaned-up rip
filenames, extracted thumbnails, and a guaranteed browser-playable copy produced
by a built-in ffmpeg worker.

Key characteristics:

- Multiple named libraries, each typed as yt-dlp =downloads= or MakeMKV =discs=.
- Full-text search across every library at once, over yt-dlp =info.json= and
  Kodi =.nfo= metadata plus filenames.
- Multi-title disc rips grouped into one item with a pick-the-main-title flow.
- Built-in disc ripping: insert a disc and MakeMKV rips every title into its own
  per-disc directory, with the disc analysis kept beside the MKVs and a Rips
  page showing progress and history.
- Disc identity from TMDB: a ripped disc gets a Kodi =.nfo=, poster, and fanart
  and is renamed to its title, automatically when the match is confident and
  through a candidate picker on the Rips page otherwise.
- In-browser playback with codec-aware source selection; masters that browsers
  cannot play get an automatically derived H.264/AAC compat copy (the original
  file is never modified).
- A rebuildable SQLite index kept current by filesystem watching; sidecar files
  remain the source of truth.

* Installation

** From source

Requires Rust (stable) and =cargo=.

#+begin_src sh
git clone https://github.com/LoganBarnett/loku
cd loku
cargo build --release
#+end_src

The binary is at =target/release/loku-server=.

** With Nix

#+begin_src sh
nix run github:LoganBarnett/loku
#+end_src

* Usage

Start the server, pointing it at a video library:

#+begin_src sh
loku-server --library /path/to/videos
#+end_src

Then open =http://localhost:3000= in a browser.

=--library= is single-root convenience; multi-library setups define =[[library]]=
entries in a config file instead (see =config.example.toml=) and pass
=--config=:

#+begin_src toml
[[library]]
name = "downloads"
path = "/media/videos"
kind = "downloads"

[[library]]
name = "discs"
path = "/media/rips"
kind = "discs"
#+end_src

| Flag          | Default             | Description                          |
|---------------+---------------------+--------------------------------------|
| =--config=    | discovered          | Path to the TOML config file         |
| =--library=   | (none)              | Single downloads-kind root shortcut  |
| =--listen=    | =127.0.0.1:3000=    | =host:port=, socket path, or         |
|               |                     | =sd-listen=                          |
| =--state-dir= | =STATE_DIRECTORY= / | Where the media index database lives |
|               | XDG state home      |                                      |
| =--log-level= | =info=              | Logging verbosity                    |
| =--tmdb-api-key-file= | (none)      | File holding a TMDB key; enables     |
|               |                     | disc identity resolution             |
| =--tmdb-language= | =en-US=         | TMDB language tag for metadata       |

=ffmpeg= and =ffprobe= on =PATH= enable codec probing and compat derivation;
without them Loku still browses and serves, with those features disabled and
=/healthz= reporting a degraded =media-tools= component.

** Ripping

A =[rip]= table in the config file (see =config.example.toml=) turns on disc
ripping.  The server polls the named drive through =udevadm=, and when a disc
appears it runs =makemkvcon= to scan and rip every title into
=<library>/<label>__<id>/= — the id is the disc filesystem's UUID, so box-set
discs that share a label can never overwrite one another — then folds the
directory into the index, where the compat worker picks it up like any other
video.  Each directory keeps =disc-info.txt= (the raw MakeMKV analysis) and a
=disc.json= manifest.  Re-inserting a ripped disc follows the configured policy
(=skip=, =rescan=, or =rerip=), and =POST /api/rips= reruns the disc in the
drive under any policy; the Rips page in the UI drives that.

Requirements: =makemkvcon= with its licence key and the AACS =KEYDB.cfg= under
=/.MakeMKV=, =udevadm= and =eject= on =PATH=, and read access to the drive (the
=cdrom= group).  The NixOS module's =rip= options set all of this up.  Staging,
replaced trees, and failed attempts live under the library's hidden =.rip/=
directory, which the index ignores; point other consumers of the tree (Kodi,
backups) away from it too.  Without the tools, ripping is disabled and
=/healthz= reports a degraded =rip= component.

** Identifying discs

A TMDB API key (=tmdb_api_key_file=, or the NixOS module's =tmdbApiKeyFile=)
turns on identity resolution.  Each ripped disc is fingerprinted from its
MakeMKV title table and looked up in a local cache, then searched on TMDB by the
title its label suggests.  A confident match is accepted on its own; anything
ambiguous lands in the "Needs identification" section of the Rips page, where
you can re-search and pick a candidate.  Either way the disc gets a Kodi
=movie.nfo= or =tvshow.nfo=, =poster.jpg= and =fanart.jpg=, and its directory is
renamed to =<Title (Year)>__<id>=; the NFO is what Kodi and Loku both read, so
deleting it re-queues the disc.  Use =tmdb_language= (for example =ja-JP=) for
titles in another language.  Without a key rips still complete unidentified and
=/healthz= reports a degraded =identity= component.

* Gotchas and Tradeoffs

- *The index is derived, the filesystem is truth*: metadata comes from sidecars
  (=info.json=, Kodi =.nfo=, thumbnails, =.compat.mp4=) indexed into SQLite in
  the state directory.  Deleting the state directory only costs a rescan (plus
  any manual main-title picks).
- *Derived files live beside masters*: the worker writes =foo.compat.mp4= and
  =foo.jpg= next to =foo.mkv=, so library paths must be writable by the server
  and other consumers of the same trees (e.g. Kodi) should exclude
  =*.compat.mp4= from their scans.
- *Local only by default*: the default bind is =127.0.0.1=.  Use =--listen
  0.0.0.0:3000= to expose on the LAN; for real deployments use the NixOS
  module's socket activation behind a TLS proxy with OIDC.

* Upgrading

** Elm compiler or Elm packages

The Elm frontend is compiled hermetically in Nix.  Two files in =frontend/=
describe the dependency set and must be kept in sync with =elm.json=:

- =elm-srcs.nix= — one =sha256= + =version= entry per package, generated by
  =elm2nix convert=.
- =registry.dat= — a snapshot of the Elm package registry, generated by =elm2nix
  snapshot=.

After adding, removing, or bumping any package in =elm.json=:

#+begin_src sh
cd frontend
elm2nix convert 2>/dev/null > elm-srcs.nix
elm2nix snapshot
git add elm-srcs.nix registry.dat
git commit -m "Update elm-srcs.nix and registry.dat for new dependencies"
#+end_src

Both =elm2nix= and =elm= are available in the Nix dev shell (=nix develop=).

The Nix build uses =pkgs.elmPackages.fetchElmDeps= to assemble an offline
=ELM_HOME= from the packages listed in =elm-srcs.nix=, then compiles with =elm
make --optimize=.  No generated JavaScript lives in the repository.
